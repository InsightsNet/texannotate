# LPSB Development Lessons Learned (2026-01-06)

This document captures the pitfalls encountered and solutions found during table extraction development.

---

## Issue 1: Table Row Detection via LaTeX Hooks

### Problem
Attempting to detect table row boundaries by hooking LaTeX internal commands failed:

1. **`\everycr` hook**: Does not fire inside `tabular` environment
2. **`\@tabularcr` hook**: Timing issues cause cells to be assigned to wrong rows
3. **`\multicolumn`/`\multirow` hooks**: Interfere with visual rendering

### Root Cause
LaTeX alignment environments (`tabular`, `longtable`) are extremely sensitive to injected tokens. Any hook that modifies the token stream during alignment can:
- Cause visual artifacts (extra lines, missing rules)
- Break cell spacing and alignment
- Interfere with `\hline`/`\cline` rendering

### Solution
**PDF-side extraction** using `pdfplumber`:
- Extract table structure from the rendered PDF
- Automatically detects colspan/rowspan via `None` cells
- No LaTeX hook complexity

```bash
python extract_cells.py main.pdf -o main.lpsb-table.json
```

### Files Affected
- `lpsb-luatable.sty`: Removed internal row tracking hooks
- `extract_cells.py`: New PDF-side extraction script (later deleted by user)

## Issue 2: Lua hpack_filter Cannot Detect Row Boundaries

### Problem
The `hpack_filter` callback in LuaTeX captures each table cell, but:
- All cells are accumulated without row delimiter information
- Results in all cells being placed in a single row

### Root Cause
`hpack_filter` is called when TeX packs content into horizontal boxes. Row breaks (`\\` or `\cr`) happen at a different stage and don't trigger this callback.

### Solution
Two approaches:

1. **Log markers** (implemented in `lpsb-luatable.sty`):
   ```latex
   \typeout{LPSB-ROW-END: table=\lpsb@tblid, row=\the\lpsb@rowcount, page=\thepage}
   ```
   Then post-process with Python.

2. **PDF-side extraction** (preferred): Bypass the problem entirely.

## Issue 3: biblatex `.bbl` Format Version Mismatch

### Problem
Compilation generates 100,000+ pages with raw biblatex internal data printed as text:
```
author2hash=3d2b0d74381c87ef5e9d769bac58ab7afamily='t Hout...
```

### Root Cause
- The `.bbl` file was generated by an older biber (`biblatex bbl format version 3.1`)
- TeX Live 2025 biblatex expects a newer format
- biblatex fails to parse the `.bbl` and prints raw internal data

### Symptoms
- Log shows: `Package biblatex Warning: File '*.bbl' is wrong format`
- Page numbers explode to 100,000+
- Each bibliography entry becomes multiple pages of raw data

### Solution
Use matching TeX Live version:
- Format 3.1 → TeX Live 2022/2023
- Check `.bbl` header: `% $ biblatex bbl format version X.Y $`

Script detection (in `batch_compile_all.sh`):
```bash
bbl_version=$(head -3 *.bbl | grep "biblatex bbl format version" | grep -oE "[0-9]+\.[0-9]+")
```

## Issue 4: LPSB Package Load Order

### Problem
Loading `lpsb-luatable` before `lpsb` can cause undefined control sequences.

### Root Cause
`lpsb-luatable` depends on counters and macros defined in `lpsb.sty`.

### Solution
Always load in this order:
```latex
\usepackage{lpsb}
\usepackage{lpsb-luatable}   % Optional
\usepackage{lpsb-luamath}    % Optional
```

## Summary: Table Extraction Approaches

| Approach | Row Detection | colspan | rowspan | Visual Safety | Recommended |
|----------|---------------|---------|---------|---------------|-------------|
| Lua hpack_filter only | ❌ | ❌ | ❌ | ✅ | No |
| LaTeX `\@tabularcr` hook | ⚠️ Timing issues | ❌ | ❌ | ⚠️ | No |
| Log markers + post-process | ✅ | ❌ | ❌ | ✅ | Partial |
| **PDF-side (pdfplumber)** | ✅ | ✅ | ✅ | ✅ | **Yes** |

## Quick Reference: Common Failure Patterns

| Symptom | Likely Cause | Solution |
|---------|--------------|----------|
| 100k+ pages | biblatex format mismatch | Use matching TeX Live version |
| `[?]` citations | natbib not resolving | Run multiple passes |
| Extra table lines | AddToHook on tabular | Avoid tabular hooks |
| Missing row separators | No row detection | Use PDF extraction |
| Undefined `\lpsb@*` | Wrong package order | Load `lpsb` first |
