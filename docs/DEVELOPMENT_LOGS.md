# Development Lessons & Technical Insights

This document records key technical challenges encountered during LPSB development, the symptoms of failure, and the architectural decisions made to resolve them. It serves as a detailed guide for future contributors to understand the "why" behind the code.

---

## 1. LaTeX Instrumentation Pitfalls

### The `\AddToHook` Trap in Alignment Contexts

**The Problem**: We initially used `\AddToHook{env/tabular/begin}` to inject a tracking ID generation macro.
```latex
% The faulty hook
\AddToHook{env/tabular/begin}{%
    \stepcounter{lpsbTabularCount}%
    \edef\lpsb@tblid{Table-\the\lpsbTabularCount}% <--- EXPLOSION
}
```

**Symptoms**:
-   **Visual Artifacts**: Tables rendered with **2 extra vertical lines** on the left side.
-   **Ghost Rows**: `longtable` environments displayed empty "ghost" rows with partial borders.
-   **Scope Leaks**: Cell content sometimes leaked into the margin.

**Technical Deep Dive**:
Directly modifying the state inside a `tabular` begin hook is dangerous because this hook executes largely *within* the construction of the underlying `\halign` preamble. LaTeX's alignment mechanism relies on scanning tokens (`&`, `\cr`, `#`) to build columns.
Executing an `\edef` (full expansion) at this specific moment disturbs the scanner or inserts frozen relaxation tokens that `\halign` misinterprets as part of the column template. This results in the creation of spurious "empty" columns, manifesting as extra vertical bars.

**The Solution: Direct Command Patching**
We completely abandoned `\AddToHook` for tables. Instead, we wrap the primitive environment commands. This ensures our ID generation code runs **before** `\halign` initialization begins.

```latex
\let\lpsb@orig@tabular\tabular
\renewcommand{\tabular}[2][]{%
    % 1. Generate ID safely (outside alignment scope)
    \global\advance\lpsbTabularCount by 1
    \xdef\lpsb@currentTblId{Table-\the\lpsbTabularCount}%
    
    % 2. Start tracking
    \directlua{lpsb.begin_table("\lpsb@currentTblId")}%
    
    % 3. Call original tabular
    \lpsb@orig@tabular[#1]{#2}%
}
```

## 2. Compilation Pipeline Architecture

### The "Gold PDF" Strategy (Two-Pass Compilation)

**The Challenge**:
-   **Goal**: Extract MathML for accessibility.
-   **Constraint**: `luamml` (LuaMathML) requires `lualatex`.
-   **Reality**: Most older arXiv papers use `pdflatex`-specific packages (`inputenc` with `utf8x`, `pstricks`, `microtype` quirks) that crash `lualatex` or produce corrupted output (missing characters, wrong fonts).

**Failed Attempt (Single Pass)**:
Trying to compile everything with `lualatex` resulted in ~40% failure rate on older corpora. PDFs had missing glyphs (cid:X) or layout shifts.

**Successful Architecture**:
Decouple the **Visual/Structural Truth** from the **Semantic Enrichment**.

1.  **Pass A (Gold Standard)**: `pdflatex`.
    -   Produces the user-facing PDF.
    -   Produces `main.lpsb.json` (document skeleton: sections, paras, floats).
    -   *Success Rate*: >95%.

2.  **Pass B (Enrichment)**: `lualatex`.
    -   Runs in the background.
    -   Produces `main.lpsb-math.json` (MathML) and `main.lpsb-table.json` (coordinates).
    -   Output PDF is discarded (it might be broken).
    -   Errors are tolerated; if it crashes, we just lose MathML, not the whole document structure.

3.  **Merge**: Python script stitches Pass B data onto Pass A skeleton using stable IDs (`Equation-1`, `Table-1`).

## 3. Dealing with Legacy TeX Environments

### TeX Live Version Dependency (`biblatex`)

**The Symptom**: A paper compiles, but the PDF result is **100,000+ pages** long, consisting entirely of raw text like `author2hash=3d2b...`.
**The Error**: `Package biblatex Warning: File 'paper.bbl' is wrong format version - expected 3.3, found 3.1`.

**Root Cause**:
arXiv sources often include a pre-generated `.bbl` file (created by `biber`). `biblatex` is extremely version-strict; a `.bbl` generated by `biber` from TL2021 cannot be read by `biblatex` in TL2023. When reading fails, `biblatex` sometimes dumps the raw bbl content into the document body.

**Resolution Algorithm**:
We implemented a "Version Sniffer" script (`batch_compile_all.sh`):

1.  **Check Metadata**: Look for `00README.json` (new arXiv standard).
2.  **Check Artifacts**: If `.bbl` exists, grep the header.
    -   `biblatex bbl format version 3.1` → Use **Docker TL2022**.
    -   `biblatex bbl format version 3.2` → Use **Docker TL2023**.
    -   `biblatex bbl format version 3.3+` → Use **Docker Latest**.
3.  **Fallback**: Default to Latest.

## 4. Robust JSON Generation in TeX

### Roman Numeral Page Numbers

**The Bug**:
Code: `\lpsbWrite{ "page": \thepage }`
Result for page 3: `{ "page": 3 }` (Valid JSON)
Result for page ii: `{ "page": ii }` (**Invalid JSON** - parser expects value)

**Fix**: Always treat page numbers as strings.
Code: `\lpsbWrite{ "page": "\thepage" }`
Result: `{ "page": "ii" }` (Valid)

### The Backslash Nightmare

**The Bug**: Section titles containing commands like `\section{Impact of \textsc{AI}}`.
Naive extraction: `title": "Impact of \textsc{AI}"`
JSON Parser Error: `\t` is interpreted as a tab character escape; `\e` is invalid.

**Investigation**: `\detokenize` helps, but `\texorpdfstring{TeX}{PDF}` creates complex nested expansions that `\detokenize` can mangle or leave effectively unreadable.

**Strategy**:
1.  **Filter Internal Macros**: We hook `\@ssect` (starred sections) and inspect the title. If it starts with `\` (e.g., `\contentsname`), we ignore it. This prevents TOC headers from polluting the section tree.
2.  **Specific Hooks**: For problematic templates like CVPR, which wrap user titles in `\texorpdfstring{\hskip...}{Title}`, we hook the wrapper command directly to extract the clean `Title` argument *before* it gets wrapped.

## 5. Table Extraction Reality Check

### Source vs. PDF Extraction

**The Dilemma**:
-   **LaTeX Source**: Knows the *semantic* content perfectly (commands, formulas).
-   **PDF Output**: Knows the *physical* layout perfectly (rows, cols, spans).

We tried to extract table structure entirely from LaTeX (LuaTeX `hpack_filter`).
**Failure Mode**:
-   **Empty Cells**: `hpack_filter` only fires for boxes with content. Empty cells (`&&`) are invisible to the callbacks. This breaks column counting.
-   **Row Breaks**: Hooking `\\` or `\cr` causes the same artifacts as `\tabular` hooks. Without explicit row breaks, we get a flat stream of cells.

**Winning Strategy**:
Use **PDF-side extraction** (`pdfplumber`) as the ground truth for the grid structure (rows/cols/spans), and use the **LaTeX stream** to populate the cell content. This "Hybrid" approach gives the best of both worlds:
1.  PDF defines the skeleton (Table T has 5 rows, 3 cols).
2.  LaTeX provides the rich text (Cell (2,1) contains `$E=mc^2$`).
